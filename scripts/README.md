# 하니스

| 스크립트 | 용도 |
|---|---|
| `lpt-linux.sh` | 최소 리눅스 게스트로 LPT 를 때린다. 이 저장소의 주력 도구 |
| `lpt-xp.sh` | Windows 게스트 A/B. 모니터로 키를 주입하고 응답성을 감시한다 |
| `lpt-trace.sh` | Windows 게스트에 `-trace parallel_ioport_*` 만 걸어 띄운다 |
| `stall-sink.py` | **막히는 싱크.** 연결은 받되 읽지 않는다. 프리즈의 방아쇠 |
| `monctl.py` | HMP 모니터 조종 — 키 주입, 화면 캡처, 응답성 폴링 |

## 환경변수

| | |
|---|---|
| `LPT_BIN` | 시험할 `qemu-system-i386` 경로 (필수) |
| `WORK_DIR` | `images/` 를 담은 디렉토리 (Windows 하니스) |
| `LPT_CHARDEV` | `-chardev` 인자 전체를 갈아끼운다. 기본은 파일 싱크 |
| `NOTRACE=1` | 트레이스를 끈다. **약 50배 빠르다** |
| `FLOODN` / `IRQN` | `flood`·`irq` 프로브의 8KB 블록 수 |
| `TMO` | QEMU 를 `timeout` 으로 감싸는 초 |
| `MACH` | 머신 타입 (기본 `q35`) |

## 알아둘 것

**바이너리를 기록한다.** 런마다 `logs/<태그>-binary.txt` 에 버전·sha256·mtime 이
남는다. A/B 도중 누가 공용 빌드 디렉토리를 재빌드하면 대조군이 조용히 오염되는데,
그 사고를 실제로 겪고 넣은 장치다.

**트레이스는 바이트당 6줄쯤 쌓인다.** 512KB 출력에 160MB 로그가 나온다.
프리즈 재현처럼 대량 출력을 할 때는 `NOTRACE=1` 을 쓸 것.

**실행 중인 셸 스크립트를 편집하지 말 것.** bash 는 스크립트를 바이트 오프셋으로
이어 읽는다. 돌고 있는 중에 고치면 엉뚱한 지점부터 읽어 실행이 깨진다.
(이것도 실제로 런을 하나 날리고 배웠다.)

**`pkill -f <패턴>` 을 조심할 것.** 패턴이 자기 셸의 명령줄에도 걸려 셸까지 죽는다.
`/proc/<pid>/comm` 으로 거르거나 모니터의 `quit` 을 쓸 것.

**Windows 게스트는 항상 `snapshot=on`.** 프리즈 시험은 강제 종료가 반복된다.
